# 사람 테스트 계획

인자: `$ARGUMENTS`

코드와 문서를 고치지 않는다. 계획은 대화에 출력한다.

## 절차

1. 근거 문서를 읽는다.
   - 마일스톤: 해당 마일스톤 문서의 완료 조건과 통합 검증 시나리오, 관련 상세 명세
   - E2E: 모든 기능 마일스톤의 통합 검증 시나리오와 `Docs/Design/Test/`
2. 실행 방법과 절차를 실제 코드, 설정, 명령으로 확인한다.
3. 다음 형식으로 작성한다.

| 번호 | 수행 | 기대 결과 | 절차 확인 | 데이터 위험 |
|---|---|---|---|---|

## 작성 규칙

- `절차 확인`에는 `에이전트 확인: <명령과 결과>` 또는 `미확인`을 적는다.
- 화면, 외부 앱, 다른 PC의 절차는 에이전트가 실제로 보지 않았으면 `미확인`으로 적는다. 기억이나 추측으로 안내하지 않는다.
- 실제 데이터나 다른 프로젝트에 영향을 줄 수 있는 절차는 영향 범위와 되돌리는 방법을 `데이터 위험`에 적는다.
- 마지막에 실패를 발견했을 때 남길 정보(재현 절차, 로그 위치)를 적는다.
