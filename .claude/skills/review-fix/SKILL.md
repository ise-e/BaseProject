# 리뷰 수정

인자: `$ARGUMENTS`

이 스킬 실행은 수정 결과를 커밋하라는 사용자의 명시적 지시다(`CLAUDE.md` 8번). 원격 저장소 작업은 하지 않는다.

## 절차

1. 이 세션에서 대상 코드를 구현했거나 리뷰했다면 멈추고 새 세션에서 실행하도록 안내한다.
2. `.local/reviews/<ID>-review.md`를 읽는다. 없으면 멈추고 `/milestone-review <ID>`를 먼저 실행하도록 안내한다.
3. 고칠 항목을 정한다.
   - `수정 대상` 전체
   - `사용자 결정 필요` 중 인자로 고른 항목. 고르지 않은 항목은 바꾸지 않는다.
4. 고친다. 지적이 틀렸거나 고칠 수 없으면 코드를 바꾸지 않고 이유를 보고한다.
5. 고칠 파일에 사용자의 미커밋 변경이 있으면 수정 전에 멈추고 브리핑한다.
6. 관련 테스트와 검증을 실행한다. 실패하면 커밋하지 않고 원인과 결과를 보고한다.
7. 직접 바꾼 경로만 커밋한다. 새 파일은 `git add <path>` 후, 커밋은 `git commit -F <메시지 파일> -- <paths>`로 한다.
   - 제목: `FIX: <ID> 리뷰 후속 수정`
   - 본문: `결함 수정`, `사용자 결정 반영`으로 나누고 항목마다 변경 이유를 적는다. 마지막에 검증 명령과 결과를 적는다.
8. `CLAUDE.md` 6번 구조로 보고하고, 다음 단계로 새 세션의 `/milestone-review <ID> 재리뷰`를 안내한다.
