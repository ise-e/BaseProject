기본적인 작업 프로세스 :
    Project Planning
    (프로젝트 기획 문서 작성)
    ↓
    Use Case scenario
    (유즈케이스 시나리오 작성) * 다만 해당 단계는 상황에 따라 상세 명세에 편입될 수 있음
    ↓
    Detailed Specification
    (상세 명세)
    ├─ Actor
    ├─ Trigger
    ├─ Precondition
    ├─ Main Flow
    ├─ Alternative / Exception Flow
    ├─ Postcondition
    ├─ Business / Data Rules
    └─ Acceptance Criteria (필요 시)
    ↓
    Domain Model
    (도메인 개념 모델)
    ↓
    Invariant
    (불변 조건)
    ↓
    Dynamic Design
    (동적 설계)
    ├─ Sequence Diagram
    └─ State Diagram
    ↓
    Responsibility Assignment
    (책임 할당)
    ↓
    Design Class Diagram
    (설계 클래스 다이어그램)
    ↓
    Test Design
    (테스트 설계)
    ↓
    Task Decomposition
    (작업 분해)
    ↓
    AI Implementation
    (AI 구현)
    ↓
    Verification
    (검증)
    ↓
    Measurement
    (측정)
    ↓
    Architecture / Design Revision ** 아키텍쳐 문서는 프로젝트 전반에서 지속적으로 작성 및 갱신할 것
    (아키텍처·설계 수정)

작업자의 역할 :
    Problem (문제 정의)
    Requirement (요구사항)
    Constraint (제약사항)
    -> 상세 명세 작성

```
Architecture (아키텍처 설계)
Invariant (불변 조건)
Acceptance Criteria (인수 조건 / 완료 기준)
Task Decomposition (작업 분할)

AI Agent (AI 에이전트 사용)

Verification (검증)
Measurement (측정)
Architecture 수정 (아키텍처 개선/수정)
```

AI의 역할 :
    Implementation (구현)
    Test Generation (테스트 생성)
    Documentation (문서화)
    Refactoring (리팩터링)
    Boilerplate (반복적 기본 코드 작성)
    Code Exploration (코드 탐색 / 코드베이스 분석)
    Alternative Proposals (대안 제시)
