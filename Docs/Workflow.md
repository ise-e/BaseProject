기본적인 작업 프로세스 :
    Project Planning
    (프로젝트 기획 문서 작성)
    ↓
    Use Case / Detailed Specification
    (유즈케이스 / 상세 명세)
    ├─ Actor
    ├─ Trigger
    ├─ Precondition
    ├─ Main Flow
    ├─ Alternative / Exception Flow
    ├─ Postcondition
    └─ Acceptance Criteria (필요 시)
    ↓
    Constraint
    (제약 조건)
    ├─ Business Constraint
    ├─ Platform Constraint
    ├─ Security Constraint
    ├─ Performance Constraint
    └─ Technical Constraint
    ↓
    Architecture
    (상위 아키텍처)
    ↓
    Domain Model
    (도메인 개념 모델)
    ↓
    Invariant
    (불변 조건)
    ↓
    Dynamic Design
    (동적 설계)
    ├─ Sequence Diagram
    └─ State Diagram
    ↓
    Responsibility Assignment
    (책임 할당)
    ↓
    Design Class Diagram
    (설계 클래스 다이어그램)
    ↓
    Test Design
    (테스트 설계)
    ↓
    Task Decomposition
    (작업 분해)
    ↓
    AI Implementation
    (AI 구현)
    ↓
    Verification
    (검증)
    ↓
    Measurement
    (측정)
    ↓
    Architecture / Design Revision
    (아키텍처·설계 수정)

작업자의 역할 :
    Problem (문제 정의)
    Requirement (요구사항)
    Constraint (제약사항)
    -> 상세 명세 작성

    Architecture (아키텍처 설계)
    Invariant (불변 조건)
    Acceptance Criteria (인수 조건 / 완료 기준)
    Task Decomposition (작업 분할)

    AI Agent (AI 에이전트 사용)

    Verification (검증)
    Measurement (측정)
    Architecture 수정 (아키텍처 개선/수정)

AI의 역할 :
    Implementation (구현)
    Test Generation (테스트 생성)
    Documentation (문서화)
    Refactoring (리팩터링)
    Boilerplate (반복적 기본 코드 작성)
    Code Exploration (코드 탐색 / 코드베이스 분석)
    Alternative Proposals (대안 제시)
